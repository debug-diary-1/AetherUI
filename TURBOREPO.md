## Introduction

AetherUI uses [Turborepo](https://turbo.build/) to manage our monorepo. Turborepo helps us optimize build times, manage dependencies, and enforce consistent workflows across packages.

## Key Features

- **Incremental builds**: Only rebuild what changed
- **Dependency-aware task execution**: Build dependencies before dependents
- **Local and remote caching**: Reuse build artifacts across machines
- **Parallel execution**: Run tasks in parallel when possible
- **Dependency graph visualization**: Understand package relationships
- **Output filtering**: Control logging verbosity with `outputMode`
- **Global environment variables**: Share env variables across tasks

## Task Configuration

Turborepo tasks are configured in `turbo.json`:

```json
{
  "$schema": "https://turbo.build/schema.json",
  "globalDependencies": ["**/.env.*local"],
  "globalEnv": ["NODE_ENV", "CI", "TURBO_FORCE", "TURBO_REMOTE_ONLY"],
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**", "build/**"],
      "inputs": ["src/**/*.{ts,tsx,js,jsx,css}", "vite.config.ts", "tsconfig.json", "package.json", "public/**/*"],
      "cache": true,
      "outputMode": "errors-only"
    }
    // More tasks...
  }
}
```

Key concepts:
- `dependsOn`: Tasks this task depends on (^ prefix means dependencies from dependent packages)
- `outputs`: Files generated by this task that should be cached
- `inputs`: Files that, when changed, should invalidate the cache
- `cache`: Whether to cache this task's results
- `outputMode`: Controls output verbosity (full, new-only, errors-only, or none)
- `globalEnv`: Environment variables accessible to all tasks
- `globalDependencies`: Files that affect all tasks (e.g., config files)

## Dependency Graph

Turborepo automatically builds a dependency graph based on your monorepo structure. You can visualize this graph using:

```bash
npm run build:deps
# or
npm run turbo:stats
```

This will generate an HTML visualization in the `build-reports` directory.

### Package Dependency Structure

Our current package dependency structure is as follows:

- `@aetherui/core`: The foundation of all components
  - Dependencies: lit
  - Dependents: adapters, docs, storybook

- `@aetherui/tokens`: Design tokens and theme definitions
  - Dependencies: [none]
  - Dependents: docs

- `@aetherui/adapters`: Framework adapters (React, Vue, etc.)
  - Dependencies: core
  - Dependents: [none]

- `@aetherui/docs`: Documentation site
  - Dependencies: core, tokens
  - Dependents: [none]

- `@aetherui/storybook`: Component development environment
  - Dependencies: core
  - Dependents: [none]

- `@aetherui/datatable`: DataTable component
  - Dependencies: lit
  - Dependents: [none]

## Caching Strategy

Turborepo uses a content-based hashing algorithm to determine if a task needs to be re-run:

1. It hashes the task's inputs
2. If the hash matches a cached result, it reuses the cached outputs
3. Otherwise, it runs the task and caches the results

To see what would be cached versus run:

```bash
pnpm run turbo:cache:status
```

To clear the local cache:

```bash
pnpm run turbo:cache:clean
```

### Cache Optimization Tips

- **Be specific with inputs**: Only include files that truly affect the task
- **Define outputs clearly**: Capture all generated files but avoid including too much
- **Use cache hit reports**: Run with `--summarize` to see cache hit rates
- **Avoid non-deterministic outputs**: Files with timestamps or random IDs will break caching

## Remote Caching

Remote caching allows sharing build artifacts across different machines and CI/CD environments, dramatically improving build times.

To set up remote caching:

```bash
pnpm run turbo:remote-cache:setup
```

For CI environments:

```bash
pnpm run turbo:remote-cache:ci
```

To use remote cache for a build:

```bash
pnpm run turbo:remote-cache:on
# or
pnpm run build -- --remote-only
```

We've added a dedicated optimization script:

```bash
pnpm run turbo:optimize
```

This script:
- Configures optimal concurrency based on your CPU
- Sets up Node.js with ideal memory settings
- Cleans stale cache entries
- Configures experimental features when appropriate
- Sets up a consistent environment for maximum cache hits

### Profile Your Build

To identify bottlenecks in your build:

```bash
pnpm run build:profile
```

This will generate a profile in the `build-reports` directory.

### Optimization Strategies

1. **Minimize task dependencies**: Only make tasks depend on what they truly need
2. **Optimize inputs/outputs**: Be specific about what files affect and are affected by each task
3. **Use package pruning**: Deploy only what's needed with `pnpm run turbo:prune:deploy`
4. **Leverage persistent processes**: For development tasks that run continuously
5. **Use concurrency controls**: Set `--concurrency=X` to control parallelism
6. **Filter for faster rebuilds**: Use `--filter` to build only what you need
7. **Use errors-only output**: Reduce noise with `outputMode: "errors-only"`

## CI/CD Integration

For optimal CI/CD performance, use:

```bash
pnpm run turbo:optimize:ci
pnpm run ci
```

This sets up the environment for maximum performance and uses remote caching.

Make sure to set these environment variables in your CI environment:
- `TURBO_TOKEN`: Your Turborepo API token
- `TURBO_TEAM`: Your Turborepo team (if using Vercel)
- `TURBO_REMOTE_CACHE_URL`: Your custom cache URL (if not using Vercel)

Example GitHub Actions setup:

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: pnpm/action-setup@v2
        with:
          version: 10.10.0
      - uses: actions/setup-node@v3
        with:
          node-version: 18
          cache: 'pnpm'
      - run: pnpm install
      - run: npm run turbo:optimize:ci
        env:
          TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}
          TURBO_TEAM: ${{ secrets.TURBO_TEAM }}
      - run: npm run ci
```

## Best Practices

### 1. Workspace Organization

- **Logical grouping**: Group related packages together
- **Clear dependencies**: Make dependencies explicit in package.json
- **Minimal workspaces**: Keep workspaces focused on single responsibilities
- **Consistent naming**: Use a consistent naming scheme for packages

### 2. Pipeline Configuration

- **Minimal dependencies**: Keep `dependsOn` lists as short as possible
- **Smart outputs**: Be precise about what files should be cached
- **Explicit inputs**: List all files that affect task outputs
- **Task consistency**: Keep task names consistent across packages

### 3. Script Usage

- **Use `filter`**: For development, build only what you need with `--filter`
- **Use `--dry-run`**: Preview what would be executed with `--dry-run`
- **Use the make helper**: Our `make` script simplifies common Turborepo operations

### 4. Performance Tips

- **Keep dependencies up-to-date**: Newer versions of Turborepo often include performance improvements
- **Prefer --concurrency over --parallel**: Controlled parallelism over unlimited
- **Use `--graph` to diagnose slow builds**: Identify bottlenecks in your dependency graph
- **Prune before deploy**: Use `turbo:prune:deploy` for deploying subsets of the monorepo

### 5. Cache Management

- **Clear periodically**: Clear the cache occasionally to prevent bloat
- **Share via remote cache**: Set up remote caching for collaborative work
- **Preserve on CI**: Use caching in CI for faster builds

## Troubleshooting

### Common Issues

1. **Cache misses**:
   - Check if all inputs are properly specified
   - Ensure deterministic builds (no random values generated)
   - Verify all environment variables are declared in `globalEnv`

2. **Dependency issues**:
   - Run `npx turbo run build --graph` to visualize the dependency graph
   - Check circular dependencies with `pnpm why`
   - Verify that `dependsOn` is correctly configured

3. **Performance problems**:
   - Use `npm run build:profile` to identify slow tasks
   - Consider splitting large packages into smaller ones
   - Check if any tasks are blocking parallel execution unnecessarily

4. **Command issues**:
   - Ensure that all tasks mentioned in `turbo.json` exist in each package.json
   - Verify that all required files are included in `inputs`
   - Check for proper `outputs` configuration

### Diagnosing Build Issues

Run the pipeline with `--dry-run` to see what would be executed:

```bash
pnpm exec turbo run build --dry-run
```

For more verbose output:

```bash
pnpm exec turbo run build --dry-run --verbosity=verbose
```

To see what's being cached and why:

```bash
pnpm exec turbo run build --dry-run --summarize
```
